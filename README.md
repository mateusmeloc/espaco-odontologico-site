# Espaço Odontológico — clinic website

One-page website for **Espaço Odontológico**, a dental clinic in Feu Rosa, Serra (ES), Brazil.
Live at **[www.espacoodontologicoserra.com.br](https://www.espacoodontologicoserra.com.br)**.

The page itself is in Brazilian Portuguese because that is the clinic's audience; this README
is in English for anyone who wants to see how it is built.

It is a static site with no framework and no runtime dependency: a single `index.html`
generated by a Python build, photos optimized as WebP, and free hosting on GitHub Pages.

## What's in it

- **12 sections** on one page: hero, warning signs, treatments, reviews, results, the clinic,
  facilities, story, principles, payment options, FAQ and location
- **Built for conversion**: WhatsApp buttons with a pre-filled message
- **Local SEO**: JSON-LD (`Dentist`, `FAQPage` with 8 questions, opening hours, address and
  coordinates), `canonical`, Open Graph and `lang="pt-BR"`
- **Responsive images**: every photo in two widths (`srcset`), lazy loading, and a fallback
  when a file fails to load
- **Light**: ~100 KB of HTML (logo inlined as a data URI); photos stay as separate
  files so the browser can cache them
- **Favicon in Google results**: square icons served as real files at the root
  (`favicon.ico`, `icon-192.png`, `apple-touch-icon.png`), because Google requires a square
  favicon that Googlebot-Image can download — a data URI gives it no file to fetch

## Structure

| Path | Purpose |
|---|---|
| `_build/template.html` | **source of the site** — this is the file you edit |
| `_build/build.py` | inlines the logo into the template and writes `index.html` |
| `_build/prepare-fotos.py` | converts the original photos to WebP (900 px and `@2x`) |
| `_build/make-icons.py` | cuts the flower from the logo and writes the square icons |
| `index.html` | final file served by Pages — **generated, do not edit directly** |
| `assets/fotos/` | optimized clinic photos |
| `assets/logo.webp` | logo, embedded as base64 in the HTML |
| `assets/logo-original.png` | high-resolution logo, source of the icons |
| `favicon.ico`, `icon-192.png`, `apple-touch-icon.png` | icons, **generated** — served as files, never base64 |
| `CNAME` | custom domain for GitHub Pages |

## Running it

```bash
python3 _build/build.py          # template + assets -> index.html
open index.html                  # opens straight in the browser, no server needed
```

The build aborts (instead of producing a broken site) if a file is missing or a placeholder
is left in the template. It also aborts if a favicon link is inline base64 or points to a
missing or non-square file — the three ways the icon silently disappears from Google.

If the logo changes, regenerate the icons (needs [uv](https://docs.astral.sh/uv/), which
fetches Pillow into a throwaway environment — nothing is installed in the project):

```bash
uv run _build/make-icons.py      # assets/logo-original.png -> favicon.ico, icon-192.png, apple-touch-icon.png
```

Google can take days or weeks to pick up a new favicon. To speed it up, request indexing
of the home page in Google Search Console (URL Inspection).

To add or replace photos, put the originals in `fotos-originais/` (a local folder,
**outside git**) and run:

```bash
python3 _build/prepare-fotos.py  # originals -> assets/fotos/*.webp
python3 _build/build.py
```

`prepare-fotos.py` uses `sips` (ships with macOS) and `cwebp` (`brew install webp`), and only
reprocesses what changed.

## Publishing

Pages serves `main` from the repository root. DNS is managed at Registro.br: `www` is a CNAME
to GitHub Pages and the bare domain uses the Pages IP addresses. To ship a change: edit the
template, run the build, push.

## Photos and privacy

Patient photos go on the site only with image-use authorization. The original files
(high resolution, with metadata) stay **outside the repository** — `.gitignore` blocks
`fotos-originais/`, `_drive/` and `.heic` — and only the optimized versions, stripped of
metadata, go into `assets/fotos/`.

## Compliance

The content follows the Brazilian Dental Code of Ethics: no comparison with competitors, no
prices and no promise of results. `aggregateRating` was deliberately removed from the JSON-LD,
because Google discourages a business from marking up its own rating without the individual
reviews; the block is commented out in the template in case that decision changes.
